# Урок. Файловая система: чтение, запись и безопасность

## 🎯 Цель
Научиться работать с файлами из Lua: открывать в нужном режиме, читать и писать,
переименовывать и удалять, строить пути и обходить каталоги — и делать это **безопасно**,
не теряя данные из-за незакрытого файла или неверного режима. Файлы — это то, где живут
настройки, логи, данные и результаты твоих программ.

## 📖 Теория

### 1. Файловый дескриптор и `io.open`
Файл в Lua открывают функцией `io.open(путь, режим)`. Она возвращает **файловый дескриптор**
(объект с методами) или, при ошибке, `nil` и текст ошибки:

```lua
local f, err = io.open("data.txt", "r")
if not f then
  print("Не открылся:", err)
end
```

Всегда проверяй результат: путь может быть неверным, файла может не быть, не хватать прав.
Молча проигнорированный `nil` приводит к падению на следующей строке с непонятной ошибкой.

> 💡 **Совет ментора:** в Lua функции, которые могут «провалиться», возвращают `nil, сообщение`
> первым и вторым значением. Привычка `local x, err = ...; if not x then ... end` — признак
> взрослого кода.

### 2. Режимы открытия
Второй аргумент `io.open` — режим:

| Режим | Что делает |
|---|---|
| `"r"` | чтение (по умолчанию). Файл должен существовать |
| `"w"` | запись, **обрезает файл до нуля** или создаёт новый |
| `"a"` | дозапись в конец, создаёт файл, если его нет |
| `"r+"` | чтение и запись, файл должен существовать, позиция в начале |
| `"w+"` | чтение и запись, файл обрезается/создаётся |
| `"a+"` | чтение и запись, позиция в конце |
| `"rb"`, `"wb"`… | то же самое, но в бинарном режиме (буква `b`) |

Ключевой момент: **`"w"` уничтожает старое содержимое**. Если нужно дописать — это `"a"`.

```lua
local f = assert(io.open("log.txt", "a"))   -- дописать в конец
f:write("новая строка\n")
f:close()
```

### 3. Чтение
Читать можно по форматам через `f:read(...)`:

| Формат | Значение |
|---|---|
| `"l"` или `"*l"` | одна строка **без** символа перевода строки |
| `"L"` или `"*L"` | одна строка **вместе** с `\n` |
| `"n"` | число |
| `"a"` | всё оставшееся содержимое (до конца файла) |
| число N | N байт |

```lua
local f = assert(io.open("data.txt", "r"))

local all = f:read("a")     -- весь файл целиком одной строкой
-- или построчно:
for line in f:lines() do
  print(line)
end

f:close()
```

`f:lines()` — удобный итератор по строкам файла (аналог `io.lines()` для stdin).
Помни: после чтения до конца повторный `f:read("a")` вернёт пустую строку — позиция в конце.

### 4. Запись
`f:write(...)` пишет значения без добавления переводов строк:

```lua
local f = assert(io.open("out.txt", "w"))
f:write("Имя: ", "Анна", "\n")
f:write(42, "\n")
f:close()
```

Для форматирования удобна `string.format`:

```lua
f:write(string.format("%s = %d\n", "score", 10))
```

### 5. Всегда закрывай файл — `f:close()`
Открытый файл держит ресурс операционной системы. Незакрытый файл:
- может не «сбросить» буфер на диск (данные потеряются);
- блокирует файл для других процессов;
- утекает: открыл много — упёрся в лимит дескрипторов.

```lua
local f = assert(io.open("out.txt", "w"))
f:write("данные\n")
f:close()      -- обязательно!
```

Проверить, открыт ли ещё дескриптор, можно через `io.type(f)` — вернёт `"file"`,
`"closed file"` или `nil`.

### 6. Переименование и удаление — `os.rename`, `os.remove`
```lua
local ok, err = os.rename("old.txt", "new.txt")   -- переименовать/переместить
if not ok then print("Не вышло:", err) end

local ok2, err2 = os.remove("temp.txt")           -- удалить файл
if not ok2 then print("Не вышло:", err2) end
```

Обе функции возвращают `true` при успехе и `nil, сообщение` при ошибке. `os.rename`
работает и как «переместить», если путь назначения — другой каталог (в пределах одной
файловой системы). `os.remove` удаляет файл; удалять каталоги так нельзя.

### 7. Пути
Lua **не** делает различий между `/` и `\` — за переносимость отвечаешь ты. Используй `/`:

```lua
local path = "data" .. "/" .. "users.txt"   -- data/users.txt
```

Важно: относительные пути считаются от **текущего рабочего каталога** процесса (см. урок
про терминал), а не от места, где лежит скрипт. Это частая причина «файл не найден».
Склеивать пути лучше вручную или через `table.concat`/`string.format`, избегая двойных слэшей:

```lua
local function join(...)
  local parts = { ... }
  return table.concat(parts, "/")
end
print(join("lessons", "filesystem", "data.txt"))
```

### 8. Обход каталога
В стандартной библиотеке Lua **нет** функции «список файлов в каталоге». Варианты:
1. Получить список через системную команду и `io.popen` (работает на macOS/Linux):

```lua
local pipe = io.popen("ls -1 lessons/filesystem")
for name in pipe:lines() do
  print("нашёл:", name)
end
pipe:close()
```

2. Использовать библиотеку `lfs` (LuaFileSystem), если она доступна:

```lua
local lfs = require("lfs")
for name in lfs.dir(".") do
  if name ~= "." and name ~= ".." then
    print(name, lfs.attributes(name, "mode"))
  end
end
```

Помни: `io.popen` запускает внешнюю программу — доверяй только своим путям, не подставляй
в команду непроверенный ввод пользователя.

### 9. Безопасная работа с файлами
Несколько правил, которые спасают данные:

**Проверяй результат открытия и операций.** Не игнорируй второе возвращаемое значение.

**Не перезаписывай важное сразу.** Записывай во временный файл, потом переименовывай:

```lua
local tmp = "config.txt.tmp"
local f = assert(io.open(tmp, "w"))
f:write(newContent)
f:close()
assert(os.rename(tmp, "config.txt"))   -- атомарная замена
```

Если запись оборвётся — старый `config.txt` останется целым.

**Открывай в правильном режиме.** Хочешь дописать — `"a"`, а не `"w"`.

**Закрывай файлы.** Даже при ошибке — используй `pcall` вокруг работы с файлом,
чтобы гарантированно вызвать `close`.

**Не удаляй вслепую.** Перед `os.remove` проверь, что файл существует (`io.open` вернул
дескриптор или `os.rename` сработал), и что путь именно тот, который ты ожидаешь.

### 10. Типичные ошибки новичка

| Симптом | Причина | Решение |
|---|---|---|
| `attempt to index a nil value` | `io.open` вернул `nil`, а ты вызываешь метод | проверяй `f`, используй `assert(io.open(...))` |
| файл пустой после записи | забыл `f:close()` (буфер не сброшен) | всегда закрывай файл |
| старое содержимое исчезло | открыл в режиме `"w"` вместо `"a"` | для дозаписи используй `"a"` |
| «файл не найден», хотя он есть | неверный cwd или путь | проверь путь, используй абсолютный или `pwd` |
| `f:read("a")` вернул пусто | файл уже прочитан до конца | перечитай с начала или открой заново |

## ✅ Запомнить
- `io.open(путь, режим)` возвращает дескриптор или `nil, ошибку` — всегда проверяй.
- Режимы: `"r"` чтение, `"w"` перезапись (обрезает!), `"a"` дозапись, `"b"` бинарный.
- `f:read("a")` — весь файл, `f:lines()` — построчно; `f:write(...)` пишет без `\n`.
- Всегда закрывай файл: `f:close()`, иначе теряются буферизованные данные.
- `os.rename` и `os.remove` возвращают `true` или `nil, ошибку`.
- Относительные пути считаются от текущего каталога процесса, разделитель — `/`.
- Списка файлов в стандартной библиотеке нет: `io.popen("ls")` или `lfs`.
- Безопасная запись: во временный файл + `os.rename`; дозапись — режим `"a"`.
