# Урок 12. Финальный проект — собери всё вместе

## 🎯 Цель
Доказать себе (и ментору), что лестница пройдена: построить законченное приложение,
где работают вместе модули, ООП, замыкания, ошибки, корутины и файлы.

## 📖 Теория (коротко — ты уже всё знаешь)

Финальный проект — это не новая тема, а **сборка**. Три варианта на выбор
(или предложи свой — согласуем). Требования общие:

1. **Модульность** (урок 07): минимум 3 файла-модуля + главный.
2. **ООП** (урок 08): хотя бы один класс с наследованием или метаметодами.
3. **Обработка ошибок** (урок 09): `assert` на границах + `pcall` там, где падает пользовательский ввод.
4. **Файлы** (урок 06): сохранение/загрузка состояния между запусками.
5. **Корутины или итераторы** (уроки 09–10): где-то уместны (анимация, генерация, планировщик).
6. **README проекта**: как запускать, какие команды, пример сессии.

Критерии оценки:
- 3 — работает главный сценарий, но падает на некорректном вводе / нет модулей.
- 4 — всё по требованиям, код чистый, README есть.
- 5 — плюс своя фишка: тесты-самопроверки, цветной вывод, умные ошибки,
  graceful-обработка битых файлов сохранений.

## Вариант А. 🕹️ Подземелье (текстовый roguelike)

Карта 10×10 в консоли, игрок `@`, стены `#`, монстры `M`, выход `E`.
Ходи WASD, дерись автоматически при столкновении, собери ключ — открой выход.

- Модули: `map.lua` (генерация + рендер), `entities.lua` (класс Существо → Игрок/Монстр),
  `game.lua` (цикл, ввод, бои), `main.lua` (склейка).
- Сохранение: `save.txt` (позиция, HP, уровень) + команда `load`.
- Случайность: `math.randomseed(os.time())`, генерация стен/монстров.
- Корутины: анимация «тумана войны» или походовый планировщик монстров
  (каждый монстр — задача в планировщике из урока 10!).

## Вариант Б. ✅ Таск-трекер PRO

Развитие урока 07: задачи с приоритетами, тегами, дедлайнами, сохранением в файл.

- Модули: `task.lua` (класс Задача с `__tostring`/`__lt` для сортировки),
  `store.lua` (хранение + save/load в файл через сериализацию таблиц),
  `cli.lua` (команды add/list/done/del/due/tag...), `main.lua`.
- Сериализация: придумай свой формат (строки!) и парсер через паттерны —
  или `load` для чтения (осторожно: файл свой, но валидируй через pcall!).
- Фишка на 5: просроченные подсвечиваются, `due сегодня` фильтрует,
  статистика `stats` (выполнено/всего, по тегам).
- Итераторы: `by_tag(store, "учёба")` — ленивый фильтр (урок 09!).

## Вариант В. 🌐 Мини-веб / TCP-чат (для смелых)

Lua-сокеты через `socket` (LuaSocket может отсутствовать — проверь!) или
симуляция: HTTP-парсер запросов + роутер + файловый сервер.

- Проще: напиши HTTP-парсер (паттерны!): строка запроса → метод/путь/заголовки,
  роутер `routes["/hello"] = function...`, сборка ответа. Протестируй на
  заранее записанных запросах-файлах.
- Сложнее: настоящий TCP-сервер на LuaSocket (если установишь).
- Модули: `http.lua`, `router.lua`, `handlers.lua`, `main.lua`.
- ООП: класс Request/Response. Ошибки: 400/404 через pcall вокруг хендлеров.

## ✏️ Задание

1. Выбери вариант (А/Б/В или свой) и **сообщи мне** — зафиксируем план и разобьём
   на этапы (3–4 итерации с проверками, а не «принёс всё сразу»).
2. Создай папку `project/` внутри `lessons/12-final-project/` и строй там.
3. Этап 0 (общий для всех): `project/README.md` — что строишь, структура файлов,
   как запускать. Покажи мне до кода — согласую архитектуру.
4. Дальше — итерациями: каркас → логика → сохранение → polish. Каждый этап —
   мне на проверку, как обычные уроки.
5. Финал: демо-сессия + разбор. Оценка за урок = оценка проекта.
