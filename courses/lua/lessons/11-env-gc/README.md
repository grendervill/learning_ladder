# Урок 11. Окружения, сборка мусора и отладка

## 🎯 Цель
Понять, где живут глобалы (`_ENV`), как Lua освобождает память (GC) и как копаться во внутренностях через `debug`.

## 📖 Теория

### 1. Где живут глобалы: `_G` и `_ENV`
```lua
x = 10
print(_G.x)     --> 10  (глобалы — просто поля таблицы _G!)
_G.y = 20
print(y)        --> 20  (и наоборот)
```

В Lua 5.2+ каждое чтение/запись «голого» имени идёт через **upvalue `_ENV`**:
```lua
x = 10            -- на самом деле: _ENV.x = 10
print(x)          -- на самом деле: print(_ENV.x)
```
А `_ENV` по умолчанию указывает на `_G`. Но его можно **подменить** — и получить
песочницу:

```lua
local env = {print = print}          -- только print разрешён!
env._G = env
local f = load("x = 1; print('hi')", "sandbox", "t", env)
f()                                   -- работает, но x осел в env, а не в _G!
print(x)                              --> nil (глобал не утёк!)
```

`load(chunk, name, mode, env)` компилирует строку в функцию с заданным окружением.
Так устроены песочницы (Roblox, игровые моды): чужой код выполняется, но доступа
к настоящей системе у него нет.

> ⚠️ В Lua 5.1 вместо `_ENV` была `setfenv/getfenv`. В LuaJIT (5.1-совместимый) —
> тоже `setfenv`. Помни при чтении старого кода!

### 2. Ловля случайных глобалов
Строгий режим одной строчкой — через `__newindex` на `_G` (помнишь урок 08?):
```lua
setmetatable(_G, {
  __newindex = function(_, k) error("случайный глобал: " .. k) end,
  __index = function(_, k) error("чтение несуществующего глобала: " .. tostring(k)) end,
})
-- теперь опечатка в имени сразу падает, а не создаёт тихий nil-глобал
```
(В продакшене так жёстко не делают, но как инструмент поиска багов — отлично.)

### 3. Сборка мусора (GC)
Lua сам освобождает недостижимые объекты. Управлять можно через `collectgarbage`:
```lua
print(collectgarbage("count"))   -- занято памяти, КБ
collectgarbage("collect")        -- принудительный полный цикл
collectgarbage("stop")           -- остановить GC (опасно: память растёт!)
collectgarbage("restart")        -- запустить обратно
```

Циклы жизни:
- GC **инкрементальный**: работает маленькими шагами, почти не лагает.
- Циклические ссылки (`a.b = b`) — НЕ проблема: Lua достаёт и острова мусора.
- Проблема — **утечки через глобалы/кэш**: положил в таблицу и забыл → висит вечно.

### 4. Слабые таблицы (`__mode`)
Слабая таблица не удерживает свои ключи/значения от GC:
```lua
local cache = setmetatable({}, {__mode = "v"})  -- слабые ЗНАЧЕНИЯ
do
  local obj = {data = "тяжёлая"}
  cache[1] = obj
end
collectgarbage("collect")
print(cache[1])  --> nil (объект умер, запись испарилась сама!)
```
- `__mode = "k"` — слабые ключи, `"v"` — значения, `"kv"` — оба.
- Применение: кэши, мемоизация, реестр «объект → метаданные» без утечек.
- ⚠️ Работает только для таблиц/функций/потоков/ userdata. Числа и строки в Lua
  живут иначе (строки интернируются) — их «слабость» не касается.

### 5. Финализаторы (`__gc`)
```lua
local obj = setmetatable({}, {
  __gc = function(self) print("объект умирает, закрываю ресурс") end
})
obj = nil
collectgarbage("collect")  --> объект умирает, закрываю ресурс
```
Применение: закрытие файлов/сокетов при забывчивом пользователе. Но полагаться
только на `__gc` нельзя (момент вызова негарантирован) — это страховка, не план.

### 6. Библиотека `debug`
```lua
-- трассировка:
print(debug.traceback("метка"))     -- кто меня вызвал, цепочка
-- информация о функции:
local info = debug.getinfo(print)   -- what/source/short_src/currentline...
-- локальные переменные чужого фрейма:
local name, val = debug.getlocal(1, 1)  -- уровень 1 (вызывающий), переменная 1
-- upvalue замыкания:
local name, val = debug.getupvalue(counter_fn, 1)
-- хуки (профилирование!):
debug.sethook(function() ... end, "l")  -- вызывать на каждой строке
```

Простейший профайлер — счётчик вызовов через `"c"`-хук. Полноценный — в задании!

> ⚠️ `debug` ломает инкапсуляцию: в чужом коде через getupvalue можно поменять
> приватное. Мощно для отладки, запрещено в песочницах (убери `debug` из env!).

## ✅ Запомнить
- Глобалы = поля `_G`; доступ идёт через `_ENV` (подменяется → песочница через `load`).
- GC: `collectgarbage("count"/"collect")`; утечки — через забытые ссылки, не циклы.
- Слабые таблицы `__mode="k"/"v"/"kv"` — кэши без утечек. `__gc` — страховка ресурсов.
- `debug.traceback/getinfo/getlocal/getupvalue/sethook` — рентген программы.
