# Урок. Терминал с нуля

## 🎯 Цель
Перестать бояться чёрного окна. Научиться свободно ходить по файловой системе, понимать,
где ты находишься, запускать программы (`lua` в том числе), передавать им данные через
аргументы, пайпы и редиректы, и читать коды возврата. Всё, что ты будешь делать дальше
(запускать скрипты, читать логи, собирать конвейеры), опирается на этот урок.

## 📖 Теория

### 1. Что такое терминал и оболочка
**Терминал** (или консоль) — программа, которая даёт тебе текстовое окно для ввода команд.
Внутри терминала работает **оболочка** (shell) — программа, которая читает твою строку,
разбирает её и выполняет. На macOS и Linux чаще всего это `bash` или `zsh`, на Windows — `PowerShell`
или `cmd`. Мы говорим про `sh`-подобную оболочку (macOS/Linux).

Строка приглашения обычно заканчивается символами `$` (обычный пользователь) или `#` (администратор).
Всё, что ты печатаешь, — это **команда**, состоящая из:
- **имени программы** (`ls`, `cd`, `lua`),
- **аргументов** (`ls -la`, `lua script.lua`),
- возможно, **спецсимволов** — пайпов и редиректов (`|`, `>`, `<`).

Оболочка ищет программу по имени в списке каталогов, который называется `PATH` (об этом ниже).
Если нашла — запускает. Если нет — пишет `command not found`.

### 2. Где я? — `pwd`
Прежде чем что-то делать, полезно понять, где ты находишься. У каждого процесса есть
**текущий рабочий каталог** (current working directory, cwd). Команда `pwd`
(print working directory) печатает его полный путь:

```bash
pwd
# /Users/alex/projects/learninglua
```

Важно: «текущий каталог» — это свойство *процесса*, а не файла. Когда ты запускаешь
`lua script.lua`, скрипт наследует cwd от оболочки. Многие ошибки «No such file» —
это именно неверный cwd.

### 3. Что тут лежит? — `ls`
`ls` (list) показывает содержимое каталога:

```bash
ls                # просто имена
ls -l             # подробный формат: права, размер, дата
ls -a             # включая скрытые файлы (начинаются с точки)
ls -la lessons    # комбинируем флаги и указываем каталог
ls -lh            # размеры в удобных единицах (K, M, G)
```

Типичный вывод `ls -l`:

```text
-rw-r--r--  1 alex  staff   512 Oct 22 10:00 README.md
drwxr-xr-x  3 alex  staff    96 Oct 22 10:00 lessons
```

Первый символ: `-` — файл, `d` — каталог. Дальше — права доступа, владелец, размер, дата, имя.

### 4. Ходим по файлам — `cd` и пути
`cd` (change directory) меняет текущий каталог:

```bash
cd lessons            # войти в подкаталог lessons (относительный путь)
cd lessons/01-hello-lua   # на два уровня вниз
cd ..                 # подняться на уровень вверх
cd ../..              # на два уровня вверх
cd ~                  # в домашний каталог пользователя
cd -                  # вернуться в предыдущий каталог
cd /Users/alex        # абсолютный путь
```

**Путь** — это адрес файла или каталога.

| Вид пути | Пример | Смысл |
|---|---|---|
| абсолютный | `/Users/alex/projects` | начинается с `/`, отсчёт от корня системы |
| относительный | `lessons/01-hello-lua` | отсчёт от текущего каталога |
| `.` | `.` | текущий каталог |
| `..` | `..` | родительский каталог |
| `~` | `~/projects` | домашний каталог пользователя |

> 💡 **Совет ментора:** сомневаешься, где окажется `cd` — делай `pwd` до и после. Привычка
> проверять cwd экономит часы отладки.

### 5. `PATH` — как оболочка находит программы
Когда ты пишешь `lua`, оболочка не знает заранее, где эта программа лежит. Она перебирает
каталоги из **переменной окружения `PATH`** — списка путей через двоеточие:

```bash
echo $PATH
# /usr/local/bin:/usr/bin:/bin:/opt/homebrew/bin
```

Найдёт `lua` в одном из этих каталогов — запустит. Не найдёт — `command not found`.

Полезные команды:

```bash
which lua            # показать, какой именно исполняемый файл запустится
command -v lua       # то же, переносимее
type lua             # тип: встроенная команда, файл, alias
lua -v               # версия интерпретатора
```

Если `lua` не найден, обычно нужно установить его (`brew install lua`) или добавить
каталог в `PATH`:

```bash
export PATH="$HOME/lua/bin:$PATH"   # добавить каталог в начало PATH
```

> `export` в текущей сессии действует до закрытия терминала. Чтобы сохранить навсегда,
> строку добавляют в `~/.zshrc` или `~/.bashrc`.

### 6. Запускаем Lua из терминала
Три способа:

```bash
lua script.lua              # выполнить файл
lua -e 'print("привет")'    # выполнить строку кода, не создавая файл
lua                         # открыть REPL (интерактивный режим)
```

Разберём `lua script.lua`: оболочка находит `lua` в `PATH`, передаёт ему аргумент
`script.lua`. Интерпретатор открывает файл **относительно cwd** и выполняет.

Внутри скрипта доступ к аргументам командной строки идёт через глобальную таблицу `arg`
(подробно — в уроке про скрипты):

```bash
lua args.lua one two
```

```lua
-- args.lua
print(arg[0])  --> args.lua
print(arg[1])  --> one
print(arg[2])  --> two
```

### 7. Пайпы — `|`
**Пайп** (конвейер) передаёт вывод одной команды на вход другой:

```bash
ls -l | grep README        # оставить только строки со словом README
cat data.txt | wc -l       # посчитать число строк в файле
history | tail -5          # последние 5 команд истории
```

Идея Unix: маленькие программы делают одно дело хорошо, а конвейер собирает их в цепочку.
`grep` фильтрует, `wc` считает, `sort` сортирует, `head`/`tail` берут начало/конец.

```bash
ls | sort | head -3        # первые три имени по алфавиту
```

### 8. Редиректы — `>`, `>>`, `<`, `2>`
По умолчанию у программы три потока:

| Поток | Номер | Куда идёт по умолчанию |
|---|---|---|
| stdin (вход) | 0 | клавиатура |
| stdout (вывод) | 1 | экран |
| stderr (ошибки) | 2 | экран |

Редиректы перенаправляют их:

```bash
ls > files.txt            # stdout в файл (файл ПЕРЕЗАПИШЕТСЯ)
ls >> files.txt           # stdout в конец файла (дописать)
cat < files.txt           # stdin из файла
ls /nope 2> errors.txt    # только ошибки в файл
ls /nope > out.txt 2>&1   # stdout и stderr вместе в один файл
lua script.lua < input.txt        # подать данные на stdin скрипта
lua script.lua > result.txt       # сохранить вывод скрипта в файл
```

> ⚠️ `>` затирает файл молча. `>>` дописывает. Путаница между ними — классическая потеря данных.

### 9. Коды возврата — `$?`, `&&`, `||`
Каждая программа по завершении возвращает **код возврата** (exit code):
`0` — успех, любое ненулевое число — ошибка. Оболочка хранит код последней команды в `$?`:

```bash
ls lessons
echo $?          # 0 — успех
ls /nope
echo $?          # 1 (или 2) — ошибка
```

Коды позволяют строить логику прямо в командной строке:

```bash
lua script.lua && echo "успех"      # выполнить второе, только если первое вернуло 0
lua script.lua || echo "провал"     # выполнить второе, только если первое вернуло не 0
```

В Lua скрипт возвращает код через `os.exit(код)` (подробно — в уроке про скрипты).

### 10. Типичные ошибки новичка

| Сообщение | Причина | Что делать |
|---|---|---|
| `command not found` | программы нет в `PATH` | `which lua`, установить или поправить `PATH` |
| `No such file or directory` | неверный cwd или опечатка в пути | `pwd`, `ls`, проверь путь |
| `Permission denied` | нет прав на запуск/запись | `chmod +x файл`, проверь владельца |
| `cd: no such file or directory` | каталога нет | `ls`, проверь регистр и путь |
| вывод ушёл «не туда» | перепутаны `>` и `>>`, или нужен `2>` | проверь редиректы |

## ✅ Запомнить
- `pwd` — где я, `ls` — что рядом, `cd` — перейти.
- Абсолютный путь начинается с `/`, относительный — от текущего каталога; `.` и `..` — это каталоги.
- `PATH` — список каталогов, где оболочка ищет программы; `which lua` покажет, что запустится.
- `lua file.lua` запускает файл, `lua -e '...'` — строку, `lua` — REPL.
- `|` соединяет команды, `>` перезаписывает файл, `>>` дописывает, `2>` ловит ошибки, `<` подаёт stdin.
- Код возврата `0` — успех, не `0` — ошибка; `&&` и `||` ветвят по нему.
