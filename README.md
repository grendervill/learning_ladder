# 🪜 Лестница обучения

Локальный многотемный учебный кабинет: курсы, ИИ-наставник, практика и прогресс.
Данные и прогресс хранятся на диске. ИИ подключается отдельно — локальный
OpenCode или API выбранного провайдера; собственного облака и телеметрии
у приложения нет.

[![desktop](https://github.com/grendervill/learning_ladder/actions/workflows/desktop.yml/badge.svg)](https://github.com/grendervill/learning_ladder/actions/workflows/desktop.yml)
[![License: GPL-3.0](https://img.shields.io/badge/license-GPL--3.0-blue.svg)](LICENSE)

## Что это

«Лестница обучения» — настольное приложение и локальный веб-кабинет, в котором
можно вести несколько независимых курсов. У каждого курса своя карточка, главы,
уроки, задания, наставник, среда запуска кода и прогресс.

Всё хранится в выбранной папке проекта: курсы — обычные JSON/Markdown-файлы,
прогресс — локальная SQLite-база. Собственного облака у приложения нет.
При обращении к наставнику или конструктору контекст отправляется выбранному
OpenCode/провайдеру.

## Возможности

- главная с крупными карточками курсов, поиском и пагинацией;
- несколько курсов в одном проекте, каждый в своей папке;
- создание курса через ИИ-конструктор: тема → уточняющие вопросы → объём → сборка;
- три режима практики:
  - **разбор** — квиз 50/50: тесты и развёрнутые письменные ответы;
  - **математика** — пошаговое решение, палитра формул и KaTeX-предпросмотр;
  - **программирование** — редактор кода, запуск и LSP;
- языки и среды: Lua, C, C++, Python, JavaScript;
- ментор для каждого курса: отдельный промпт, свежая сессия на каждый запрос,
  проверка хода решения без выдачи готового ответа;
- успеваемость с фильтром по курсам, оценками, попытками и итогами занятий;
- автоматическое обновление списка моделей и уровней мышления из OpenCode
  или API провайдера;
- переключение папки проекта без потери старой папки;
- нативные установщики для macOS, Windows и Linux; сервер и Node встроены
  в приложение.

## Быстрый старт

Для разработки нужны:

- **Node.js 26+**;
- npm;
- для настольной сборки — Rust, Cargo и Tauri CLI;
- для ИИ — локальный OpenCode или API-ключ одного из поддерживаемых провайдеров;
- для курсов по программированию — соответствующие компиляторы, интерпретаторы
  и language server (Lua, gcc/g++, clangd, python3, node).

```bash
git clone https://github.com/grendervill/learning_ladder.git
cd learning_ladder
npm ci
npm run dev
```

- интерфейс: [http://localhost:5173](http://localhost:5173)
- API: `http://127.0.0.1:4174`

В режиме разработки папка проекта — это сам репозиторий. Рабочие данные лежат
в `data/` и не попадают в Git.

## Настольное приложение

```bash
npm run tauri:build
```

Сборка сначала готовит frontend, серверный бандл, веб-ресурсы и Node 26 для
текущей платформы, затем собирает установщик:

| Платформа | Форматы |
|---|---|
| macOS Apple Silicon | `.app`, `.dmg` |
| Windows x64 / arm64 | NSIS |
| Linux x64 / arm64 | AppImage, DEB |

Внутри приложения уже есть Node, сервер и frontend. Для запуска готовой сборки
не нужны исходники или отдельно установленный Node. OpenCode, компиляторы и
language server остаются внешними — приложение показывает их состояние
в проверках.

Сборки не подписаны: macOS Gatekeeper и Windows SmartScreen могут показать
предупреждение.

DEB-пакет устанавливается под именем `learning-ladder`: `dpkg` не принимает
кириллицу в имени пакета. В меню приложение по-прежнему называется
«Лестница обучения».

### Первый запуск

Приложение создаёт папку проекта:

- macOS/Linux: `~/Documents/Лестница обучения`;
- Windows: `%USERPROFILE%\Documents\Лестница обучения`.

Внутри появляются `courses/`, `data/`, `prompts/`, `reports/` и
`.opencode/agents/`. Новый проект начинается с пустой главной — первый курс
создаётся через мастер.

Путь к выбранной папке хранится в конфиге приложения:

- macOS: `~/Library/Application Support/learning-ladder/config.json`;
- Windows: `%APPDATA%\learning-ladder\config.json`;
- Linux: `$XDG_CONFIG_HOME/learning-ladder/config.json`.

Сменить папку можно в «Настройках → Папка проекта»; старая папка остаётся
на месте.

### CI-сборки

Workflow [`.github/workflows/desktop.yml`](.github/workflows/desktop.yml)
собирает матрицу платформ вручную (`workflow_dispatch`) или по тегу `v*`:

- `aarch64-apple-darwin`;
- `x86_64-pc-windows-msvc` и `aarch64-pc-windows-msvc`;
- `x86_64-unknown-linux-gnu` и `aarch64-unknown-linux-gnu`.

Готовые установщики публикуются как артефакты workflow.

## Как устроено обучение

1. На главной выбери курс или создай новый.
2. В курсе открой урок: теория → вопросы → практика.
3. Выполни практику и ответь на вопросы.
4. Нажми «Сдать урок» — наставник проверит понимание и поставит оценку.
5. Оценка 4+ открывает следующий урок/главу.
6. В «Успеваемости» смотри оценки, попытки и итоги занятий.

Для курсов-разборов практикой является сам квиз 50/50. Для математики — шаги
решения с формулами. Для программирования — код, запуск и диагностика.

### Наставник

У каждого курса свой системный промпт. Наставник объясняет и задаёт наводящие
вопросы, но не выдаёт готовое решение. Каждый запрос получает отдельную сессию,
поэтому курсы не смешивают контекст.

## Создание курса

Мастер запрашивает тему, задаёт 2–3 уточняющих вопроса с вариантами и просит
выбрать объём. Один запуск мастера создаёт **один курс** — одну карточку, одну
папку и одного наставника. Несколько курсов создаются несколькими запусками.

Во время генерации мастер остаётся открытым; сборку можно отменить. Курс
сохраняется только после успешной генерации всех уроков. Задания генерации
хранятся в памяти сервера, поэтому перезапуск сервера во время сборки
отменяет её.

## Настройки

Глобальные вкладки:

- **Проверки** — инструменты, нейросеть, конструктор и папка проекта;
- **Нейросеть** — провайдер, ключ, модель и уровень мышления;
- **Создать курс** — запуск мастера;
- **Конструктор** — системный промпт ИИ-конструктора;
- **Папка проекта** — текущий путь, смена папки и нативный выбор каталога.

У каждого курса есть собственные настройки: карточка, промпт наставника, среда
запуска, LSP и проверки курса.

## Модели и уровни мышления

- **OpenCode** — список моделей и варианты мышления (`low`, `medium`, `high`,
  `xhigh`, `max`, …) берутся из локального сервиса OpenCode и его подписки.
- **DeepSeek, Anthropic, OpenAI, Google Gemini, совместимый сервис** — модели
  запрашиваются через API провайдера, уровни определяются по возможностям
  модели.
- Если ключ не сохранён или API недоступен, показывается сохранённый список;
  модель можно ввести вручную.
- Ключи хранятся только в `data/settings.json` проекта и маскируются
  в интерфейсе.

Подробности — в «Настройки → Нейросеть».

## Папка проекта и файлы

```text
<project>/
├── courses/
│   ├── lua/                    # встроенный пример курса
│   │   ├── course.json
│   │   ├── mentor.md
│   │   ├── course/chapters.json
│   │   └── lessons/<урок>/
│   │       ├── README.md
│   │       ├── quiz.json
│   │       └── tasks/
│   └── <course-id>/            # сгенерированный курс
│       ├── course.json         # главы, уроки, квизы, задания и файлы
│       └── mentor.md
├── data/
│   ├── learninglua.db          # прогресс, ответы, попытки
│   ├── settings.json           # настройки и ключи (локально)
│   └── workspaces/             # рабочие копии для запуска и LSP
├── prompts/                    # пользовательские промпты
├── reports/                    # итоги занятий
└── .opencode/agents/           # служебные агенты наставника/конструктора
```

- В сгенерированном курсе весь материал лежит в `course.json`.
- В старом формате Lua теория, квиз и задания лежат отдельными файлами.
- В репозитории есть пример `courses/lua`; новый проект, созданный
  приложением, начинается без курсов.
- `data/`, `reports/`, `.env` и настройки не коммитятся в Git.
- Прогресс и ответы находятся в базе, а не переписывают `course.json`.
- Просматривать курсы можно любым файловым менеджером и редактором.

## Разработка

```bash
npm run dev          # сервер + Vite
npm test             # unit-тесты
npm run test:e2e     # Playwright, нужен установленный Chromium
npm run typecheck    # TypeScript
npm run build        # production frontend
npm run tauri:dev    # приложение в режиме разработки
npm run desktop:prepare  # только ресурсы для desktop-сборки
npm run tauri:build  # установщик текущей платформы
```

### Стек

- React 19, TypeScript, Vite;
- Express 5, SQLite через встроенный `node:sqlite`;
- Tauri 2 + Rust для настольного приложения;
- CodeMirror 6, KaTeX, highlight.js;
- OpenCode Client для локальной подписки и моделей;
- Vitest и Playwright.

### Структура репозитория

```text
src/        интерфейс React
server/     API, БД, курсы, наставник, LSP
shared/     общие пресеты сред, тем и иконок курсов
src-tauri/  настольная оболочка и Rust
scripts/    подготовка desktop-ресурсов
e2e/        браузерные сценарии
courses/    встроенный курс Lua и локальные курсы
```

## Безопасность и приватность

- Учебные данные, прогресс, отчёты и ключи хранятся локально.
- При вызове наставника/конструктора контекст уходит в выбранный OpenCode или
  API-провайдер; для полностью локальной работы используйте локальный OpenCode.
- Телеметрии и облачной синхронизации нет.
- API-ключи не попадают в Git: `data/settings.json` игнорируется.
- В публичном репозитории нет реальных ключей; тестовые `sk-...` — фейковые.
- Не добавляйте `data/`, `reports/`, `.env` и локальные курсы в публичный
  репозиторий.

## Ограничения текущей версии

- один запуск мастера — один курс;
- нет удаления курсов и ручного редактирования уроков через UI;
- генерация курсов и проверка ответов требуют OpenCode или API-провайдера;
- компиляторы, language server и OpenCode устанавливаются отдельно;
- сборки не подписаны;
- MSI и RPM пока не собираются из-за ограничений упаковщиков на кириллическое
  имя продукта; для Windows используется NSIS, для Linux — AppImage и DEB;
- Windows/Linux-сборки выполняются на соответствующих ОС или в CI.
