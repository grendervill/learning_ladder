# Урок 07. Модули и организация кода

## 🎯 Цель
Научиться разбивать программу на файлы, писать свои модули и понимать `require`.

## 📖 Теория

### 1. Зачем модули?
Пока всё жило в одном файле — было терпимо. Но проекты растут: телефонник, дневник,
игра... Один файл на 2000 строк — кошмар. Решение: **модуль = файл с таблицей функций**.

### 2. Анатомия модуля
Файл `mymath.lua`:
```lua
-- mymath.lua
local M = {}   -- 1. локальная таблица модуля

function M.square(x) return x * x end        -- 2. кладём функции в неё
function M.cube(x) return x * x * x end

return M       -- 3. ВОЗВРАЩАЕМ таблицу (без этого require вернёт true!)
```

Файл `main.lua` рядом:
```lua
local mymath = require("mymath")  -- имя БЕЗ .lua!
print(mymath.square(5))           --> 25
```

### 3. Как `require` ищет файлы
По шаблону `package.path` — список масок через `;`, где `?` заменяется именем модуля:
```lua
print(package.path)
-- ./?.lua;/usr/local/share/lua/5.5/?.lua;...  (примерно так)
```
Значит `require("mymath")` сначала ищет `./mymath.lua` (текущая папка!). Отсюда правило:
**запускай скрипт из папки, где он лежит**, либо расширяй путь:
```lua
package.path = package.path .. ";./libs/?.lua"  -- искать ещё и в libs/
```

Подпапки — через точку: `require("utils.strings")` ищет `utils/strings.lua`.
(В Lua 5.3+ разделитель в package.path для этого уже настроен.)

### 4. `require` кэширует!
Повторный `require("mymath")` НЕ выполняет файл заново — возвращает закэшированное
значение из `package.loaded`. Следствия:
- Циклические require (a требует b, b требует a) — боль. Проектируй без циклов.
- Перезагрузка модуля в REPL: `package.loaded["mymath"] = nil` перед повторным require.

Возвращаемое значение `require` — это то, что вернул файл. Нет `return` → вернётся `true`.
Отсюда баг новичка: забыл `return M` — получил `true` вместо таблицы и `attempt to index a boolean`.

### 5. `local` в модулях — обязательно
Всё внутри модуля объявляй `local`, наружу — только через таблицу `M`.
Случайный глобал в модуле заразит всю программу (а в уроке 11 научимся их отлавливать).

Идиома приватности: что не положил в `M` — то приватно:
```lua
local M = {}
local counter = 0          -- приватная переменная модуля (счётчик вызовов)
function M.next()
  counter = counter + 1
  return counter
end
return M
```

### 6. `do ... end` — блок ради блока
Иногда нужен локальный scope без функции:
```lua
do
  local tmp = 10 * 20
  print(tmp)
end
-- tmp здесь уже не видна
```

### 7. Типичные ошибки
| Ошибка | Причина |
|---|---|
| `module 'x' not found` | файл не в `package.path`; запуск не из той папки |
| `attempt to index a boolean/nil` | забыл `return M` в модуле |
| `attempt to call a nil value` | опечатка в имени функции / не положил в `M` |
| Циклический require | a↔b; решается выносом общего в третий модуль |

## ✅ Запомнить
- Модуль: `local M = {}`, функции в `M`, `return M`. Подключение: `require("имя")`.
- `require` ищет по `package.path` (`?` = имя) и кэширует в `package.loaded`.
- Приватность — через `local`: не попал в `M` — не виден снаружи.
