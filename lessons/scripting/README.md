# Урок. Скрипты: аргументы, потоки и коды выхода

## 🎯 Цель
Превратить «файл с кодом» в настоящую **командную программу**: чтобы скрипт принимал
аргументы, читал stdin, аккуратно писал в stdout и stderr, сообщал об успехе или ошибке
кодом возврата и запускался как обычная команда Unix. Это мост между языком и терминалом.

## 📖 Теория

### 1. Что такое скрипт
**Скрипт** — программа на интерпретируемом языке, которую запускают из командной строки.
Для Lua это файл `.lua`, который выполняется командой `lua файл.lua`. В отличие от REPL,
скрипт не ждёт ввода строк кода — он просто исполняется сверху вниз и завершается.

Простейший скрипт:

```lua
-- hello.lua
print("Привет из скрипта")
```

```bash
lua hello.lua
```

### 2. Shebang — сделать файл исполняемым
**Shebang** — первая строка файла, начинающаяся с `#!`. Она говорит системе, какой
интерпретатор запускать, если файл выполняют напрямую:

```lua
#!/usr/bin/env lua
print("Я запущен напрямую")
```

Чтобы файл можно было запускать как `./script.lua`, нужно:

```bash
chmod +x script.lua      # выдать право на исполнение
./script.lua             # теперь работает без явного "lua"
```

Почему `#!/usr/bin/env lua`, а не `#!/usr/bin/lua`? Потому что `env` находит `lua` в `PATH`
и работает, даже если интерпретатор лежит в нестандартном месте (например, в Homebrew).

> ⚠️ На Windows shebang не работает — там файл всё равно запускают как `lua script.lua`.

### 3. Аргументы командной строки — таблица `arg`
Всё, что написано после имени скрипта, попадает в глобальную таблицу `arg`:

```bash
lua greet.lua Анна 42 --verbose
```

```lua
-- greet.lua
print(arg[0])   --> greet.lua   (имя скрипта)
print(arg[1])   --> Анна
print(arg[2])   --> 42
print(arg[3])   --> --verbose
print(#arg)     --> 3           (число аргументов)
```

`arg[0]` — имя самого скрипта, `arg[1]` и далее — аргументы по порядку. `#arg` даёт
количество аргументов. Если аргументов нет, `arg[1]` равно `nil`.

Частая проверка:

```lua
local name = arg[1]
if not name then
  print("Использование: lua greet.lua ИМЯ")
  os.exit(1)   -- сообщаем об ошибке кодом возврата
end
print("Привет, " .. name .. "!")
```

Все аргументы — **строки**. Чтобы получить число, используй `tonumber`:

```lua
local n = tonumber(arg[1])
if not n then
  io.stderr:write("Нужно число\n")
  os.exit(1)
end
print(n * 2)
```

### 4. Три потока: stdin, stdout, stderr
У каждой программы три стандартных потока. В Lua они доступны так:

| Поток | В Lua | Назначение |
|---|---|---|
| stdin | `io.stdin` | входные данные |
| stdout | `io.stdout` | обычный вывод |
| stderr | `io.stderr` | сообщения об ошибках |

`print(...)` пишет в **stdout** и добавляет перевод строки. `io.write(...)` тоже пишет
в stdout, но **без** перевода строки и без табуляций:

```lua
print("a", "b")        --> a    b   (с табуляцией и \n)
io.write("a", "b")     --> ab      (без разделителя и \n)
```

Для ошибок используй stderr, а не print:

```lua
io.stderr:write("Ошибка: файл не найден\n")
```

Почему это важно: если ошибка уходит в stderr, её можно отделить от полезного вывода
редиректом `2>`, а stdout спокойно передать дальше по пайпу. Скрипт становится
«хорошим гражданином» Unix.

### 5. Чтение stdin
Читать вход можно построчно или целиком:

```lua
-- читать строку за строкой до конца ввода
for line in io.lines() do
  print("строка: " .. line)
end
```

```lua
-- прочитать одну строку
local line = io.read("l")
```

```lua
-- прочитать весь ввод до конца
local all = io.read("a")
```

`io.lines()` без имени файла читает stdin. Это позволяет писать фильтры:

```bash
cat data.txt | lua filter.lua
lua filter.lua < data.txt
```

### 6. Код возврата — `os.exit`
`os.exit(код)` немедленно завершает программу с заданным кодом возврата:

```lua
os.exit(0)   -- успех
os.exit(1)   -- ошибка
```

Соглашение: `0` — успех, `1` (или другое ненулевое) — ошибка. Без `os.exit` скрипт
завершается с кодом `0`, если не было необработанной ошибки.

```bash
lua script.lua && echo "ок"     # сработает при os.exit(0)
lua script.lua || echo "провал" # сработает при os.exit(1)
```

### 7. Обработка ошибок
Lua не заставляет объявлять исключения. Ошибку можно **вызвать** функцией `error`,
а **поймать** — функцией `pcall`.

```lua
local ok, result = pcall(function()
  error("что-то пошло не так")
end)

if ok then
  print("Всё хорошо:", result)
else
  print("Ошибка:", result)   --> Ошибка: script.lua:2: что-то пошло не так
  os.exit(1)
end
```

`pcall` возвращает два значения: `true` и результат функции — при успехе,
или `false` и сообщение об ошибке — при сбое.

`assert(условие, сообщение)` — компактный способ проверить условие и упасть с ошибкой:

```lua
local n = tonumber(arg[1])
assert(n, "нужно число")
print(n * 2)
```

Для операций с файлами, где ошибка — нормальный исход, часто удобнее `pcall` или проверка
`nil` (см. урок про файловую систему).

### 8. Автоматизация: зачем всё это
Скрипт, который читает аргументы и stdin, пишет в stdout/stderr и возвращает код, —
это **строительный блок автоматизации**. Его можно:
- вызывать из другого скрипта или из Makefile;
- встраивать в конвейер `cat data | lua filter.lua | lua sum.lua`;
- запускать по расписанию (`cron`), в CI, в хуках git;
- комбинировать с другими командами через `&&` и `||`.

Правило хорошего скрипта: **полезные данные — в stdout, диагностика — в stderr,
успех/ошибка — в код возврата.** Тогда он дружит с любым окружением.

### 9. Типичные ошибки новичка

| Симптом | Причина | Решение |
|---|---|---|
| `arg[1]` равен `nil` | аргумент не передан | проверяй `if not arg[1]`, дай подсказку по использованию |
| арифметика падает | аргумент — строка | `tonumber(arg[1])` |
| `./script.lua: permission denied` | нет права на исполнение | `chmod +x script.lua` |
| вывод и ошибки смешаны | всё пишется через `print` | ошибки — в `io.stderr` |
| скрипт «молча» провалился | не выставлен код возврата | `os.exit(1)` при ошибке |
| shebang не сработал | файл без `chmod +x` или Windows | `chmod +x`, либо `lua script.lua` |

## ✅ Запомнить
- Shebang `#!/usr/bin/env lua` + `chmod +x` позволяют запускать скрипт как `./script.lua`.
- Аргументы командной строки — в таблице `arg`: `arg[0]` — имя скрипта, `arg[1..]` — аргументы, все строки.
- `print`/`io.write` пишут в stdout; ошибки — в `io.stderr:write(...)`.
- `io.lines()` и `io.read` читают stdin — так делают фильтры для пайпов.
- `os.exit(0)` — успех, `os.exit(1)` — ошибка; `&&`/`||` ветвят по коду возврата.
- `error` вызывает ошибку, `pcall` её ловит (возвращает `ok, result`), `assert` проверяет условие.
